## 0. 30 秒版

用 Qwen2-VL-2B + LoRA，把毫米波雷达点云渲染成三视图图片，让大模型“看懂”人体运动。
E4（50 类分类）跨被试 test top1 **27.5%** / top5 **69%**（随机基线 2% / 10%），证明特征可跨人迁移。
E5 改为 RF-GPT 式生成式多任务（9 类题型），新任务平均 **0.812**，旧分类能力基本保持（top1 0.240 / top5 0.665）。
E5 诊断出两个病灶：**错误中 61% 是左右镜像混淆**、**时序运动信息不足**（movement 档位仅 0.50 且复读模板值）。
E6 对症改数据层：第 4 格图例面板换成**质心轨迹图** + 训练集**左右翻转增强**，步数同步翻倍以对齐曝光量。

## 1. 研究问题与总目标

- 目标不是训练一个 50 类分类器，而是让大模型真正理解毫米波雷达点云信号，能生成式描述人体运动；分类只是“是否看懂信号”的探针。
- 技术路线：原始点云 → 确定性渲染成图 → 视觉语言模型（Qwen2-VL-2B-Instruct）+ LoRA 微调。
- 为什么用“点云转图”而不是点云编码器：复用成熟 VLM 视觉通路，改造成本最低，先验证“视觉侧能否学到可迁移特征”这一核心假设。点云编码器路线（PointNet/Voxel+投影）作为备选，暂缓。

## 2. 数据与基线管线

- 数据集：M4Human，20 名被试，50 类动作。
- 划分：train 16 被试 / val 1（17）/ test 4（5、8、10、19）——**按被试划分**，杜绝同一人跨集泄漏。
- 规模：train 35664 条 / val 4500 / test 18000 条（对应 11888 / 1500 / 6000 张图）。
- 渲染：784×784（28 的倍数，对应 784 visual tokens），T=4 帧叠加，BEV / Front / Side 三视图，时间用颜色编码（旧蓝→新红），第 4 格原本是时间图例面板（不渲染任何标签，防泄漏）。
- 模型：Qwen2-VL-2B-Instruct，LoRA r=16 / alpha=32 / dropout=0.05，覆盖 LLM（q,k,v,o,gate,up,down）与 ViT（qkv,attn.proj,fc1,fc2），base 全冻结。
- 训练：手写循环（非 Trainer），bs=4 × accum=2，lr 1e-4 + 3% warmup + cosine，梯度裁剪 max_norm=1.0，prompt 段 labels=-100 只对答案算 loss。

## 3. 实验时间线

### E1/E2 —— 早期两轮失败与定位（结论性教训）

现象：训练 10 步内 loss 降到 0.5 后长期震荡不降；评估 top1 接近随机（约 1.7%）。
定位过程与结论：
1. **冻结 ViT** 会导致视觉通路完全不学 → top1 ≈ 随机。修正：LoRA 同时挂 ViT。
2. **训练量不足** → 模型退化为背训练集被试指纹，跨被试泛化失效。
3. **多任务混合稀释** → 生成式输出不稳定，倾向固定答案。
4. **恒定 lr 无衰减** → 训练震荡。修正：warmup + cosine。
教训：loss 下降不等于学会；唯一可靠判据是测试集 top1。

### E3 —— 二分类探针，验证视觉通路

- 做法：新增 probe_binary.py，只取 Squat / Jumping 两类做二分类过拟合测试，并支持 `--split test` 跨被试验证。
- 结果：**训练集 100%**。证明图像确实送达 LLM 且通路可学。
- 结论：前两轮失败不是代码/通路 bug，而是训练量与任务设计问题。此后才推进 50 类正式训练。
- 附带产出：渲染图从 392 升到 784，清晰度带来形态/轨迹信息显著增加。

### E4 —— 50 类细粒度分类基线（main 分支存档，tag）

- 配置：3200 步，lr 1e-4，单任务（只问动作名），outputs/e4_lora。
- 成本：约 4 小时 @ RTX 4090。
- 结果（全量 200 张 test，跨被试）：
  - **top1 27.5%，top5 69%**（随机 2% / 10%）。
  - 分动作：坐姿系列、侧走、弓步等形态稳定动作 **0.5~0.75**；太极、深蹲、自由伸展、全部行走类 **≈0**。
- 结论：学到了可跨人迁移的点云形态特征，非记忆被试指纹；**“大类能认、同类细分不足”“原地能认、移动不行”**。
- 决策：E4 单变量消融性价比低（一次训练 4h），专用点云编码器暂缓，优先走 E5 生成式路线补全理解能力。

### E5 —— 生成式多任务（feature 分支）

- 动机：分类只回答“是什么”，无法验证“看懂了多少”。改为让模型回答位置、姿态、运动、结构等多维问题。
- 做法（RF-GPT 范式，全自动、无人工标注）：
  1. 从原始点云**确定性**导出视觉可观测特征（质心 x/y/z、高度、4 帧位移、点数、空间分区等）→ `make_caption.py` 生成结构化 caption；
  2. `synthesize_instructions.py` 由 caption + 50 类动作名表合成 9 类题型题库：fine / coarse / where / posture / movement / height / dist / json / describe；
  3. 从 E4 adapter 续训 600 步（outputs/e5_lora，与 e4_lora 物理隔离，防覆盖）。
- 结果 A｜遗忘监控（train 集似然评估）：fine top1 0.35 / top5 0.67，与 E4 同口径正常波动 → 旧技能未丢。
- 结果 B｜test 集跨被试（200 题，与 E4 直接可比）：**top1 0.240 / top5 0.665**（E4 为 0.275 / 0.690，回退 3.5pp / 2.5pp，约 7 题波动，判定未遗忘）。
- 结果 C｜生成式 9 题型（各 30 题）：

| 题型 | 得分 | 读法 |
|---|---|---|
| where | 0.967 | 水平 0.97 / 深度 1.00 |
| height | 0.967 | 高度数值 |
| posture | 0.900 | 站姿/低姿态 |
| coarse | 0.867 | 大类稳固 |
| json | 0.804 | 8 字段可解析率 1.00，strict 仅 0.13 |
| dist | 0.733 | 4 帧位移 |
| movement | 0.500 | 数值 0.80，**档位仅 0.50** |
| describe | 0.267 | 动作名命中（宽松口径）|
| fine | 0.233 | 与似然口径 0.24 互相印证 |

- 新任务（6 类）平均 **0.812**。
- 结论：模型确实从渲染图学到了可跨被试泛化的结构化理解（位置/高度/姿态 >0.9），不是选择题背答案。**唯一挡路的墙是细粒度动作语义**：fine 0.233、describe 0.267、json 的 action 字段 0.30，三条证据指向同一瓶颈。

## 4. E5 之后的诊断（E6 的依据，全部有数据支撑）

用 E4 全量 200 题混淆矩阵 + E5 逐题预测交叉验证，得到三个病灶：

1. **左右镜像混淆 = 61% 的错误（88/145）**
   TOP 混淆对：`Waving right → Waving left arm`、`Sit and right leg kick → left leg kick`、`Kicking right using left leg → Kicking left using right leg`。
   左右在 BEV 图上物理存在（x 正负），但模型没学会“图中左右 = 人体左右”的约定。
2. **“Waving left arm”是预测黑洞**
   至少 16 次不同动作（乒乓球、太极、深蹲、慢走…）被预测成它。已排除类别不平衡：train 每类 672~720 条，完全均衡 → 属不确定时的默认类偏置。
3. **时序运动信息严重不足**
   - E4：Walk 族 slow↔fast 互串 8+ 次。
   - E5：movement 档位 0.50（3 类近随机）；模型复读模板值（“0.38 m” 出现 7+ 次），真实值散布 0.10~1.17 m → 没在读轨迹。
   - 根因：T=4 帧叠在一张图、时间只靠颜色区分；且第 4 格图例面板白占 25% 画面。

## 5. E6 —— 数据层优化（当前阶段）

设计原则：**不动模型架构，只改数据层**，且一次只改一类变量（数据），训练超参与曝光量保持一致可比。

| 改动 | 具体做法 | 对症 |
|---|---|---|
| 轨迹图 | 第 4 格图例面板 → BEV 质心轨迹图：4 帧质心折线 + 时间色点 + S/E 标注；自适应缩放（窗口 ≥0.5 m，原地动作保持“几乎不动”观感） | 病灶 3；movement / dist / Walk 族直接受益 |
| 左右翻转增强 | train 每图额外渲染 flip 版（点云 x 取负，xlim 镜像，**文字/坐标轴不镜像**），答案文本同步 `swap_lr` 互换 left↔right；val/test **不翻转** | 病灶 1+2（黑洞类被翻转稀释）|
| 步数对齐 | train 图片翻倍 → E4 3200→**6400 步**，E5 600→**1200 步**，保持每样本曝光次数不变 | 控制变量 |

关键实现细节（答辩可能被问）：
- 翻转必须在**点云层**做，不能整图 PIL 翻转：整图翻转会把坐标轴文字、Side 视图 y 轴语义一起镜像，造成标注与图不符。
- `swap_lr` 已验证：50 类动作名互换后仍落在 50 类内；where/json 中的 left/right 措辞同样自洽（互换前用占位符防连环替换）。
- caption 层 flip 记录同步：centroid_x 取负（空间分区 left/right 自动正确），path_len/extent 与符号无关故不变。
- 未采用“在 BEV 上画左右文字标注”：硬编码标注易与数据不符，且不如让数据驱动学习；选定翻转增强替代。
- 三 split 全部重渲染，旧图不可混用（渲染公式已变）。

产物与脚本：
- `run_e6_data.sh`：smoke 门禁（渲染 2~4 张 + caption/instruct 限量）→ full 全量（train 16 chunk 并行 + val/test），约 1-2 h。
- `run_e6_all.sh`：data → E4 6400 步（约 8h）→ E5 1200 步（约 1.5h）→ test 终评（约 15min）。
- 代码已提交 feature 分支并 push（提交 67f0683 数据层、cd110b6 一键脚本）。

预期（**推测，待实验验证，不可当结论讲**）：镜像错误若减半，fine top1 有望到 0.35~0.45；movement 档位 0.50 → 0.7+。若 E6 后 fine 仍 <0.30，再上更重手段（T=6 帧 / 7B QLoRA / 对比学习）。

## 6. 失败与放弃的方案（组会常问“为什么不…”）

- **冻结 ViT**：top1≈1.7%，已证伪。
- **恒定 lr**：震荡，已改 warmup+cosine。
- **多任务混合但训练量不足**：输出崩成固定答案，已由 E4 单任务 + E5 续训解决。
- **E4 单变量消融**：单次 4h，性价比低，暂缓。
- **专用点云编码器**（PointNet/Voxel）：未验证优劣，作为 E6 无效后的备选，不预先认定哪条路线更优。
- **BEV 硬编码左右标注**：易标错，被翻转增强替代。
- **用质心位移做原地/非原地分类**：4 帧窗口不足以区分，caption 只诚实描述可观测事实，不承担分类职责。

## 7. 答辩速查（问答对照）

- **问：你怎么优化的？**
  答：不是拍脑袋加模块，是先诊断。E5 终评暴露 fine 只有 0.23，我用 E4 全量混淆矩阵定位错误分布，发现 61% 是左右镜像混淆；又用 E5 逐题预测发现 movement 档位 0.50 且模型复读模板值，说明没读到时序。于是 E6 只改数据层：轨迹图补时序、训练集左右翻转增强消镜像偏置，步数同步翻倍控制变量。模型结构、超参不动。
- **问：27.5% 是不是太低？**
  答：跨被试 50 类，随机 2%，top5 69% 说明候选集里基本都有；瓶颈不在“看不见”，而在“同类细分”和“左右”。E5 生成式新任务 0.81 证明理解能力已在，分类器指标被细分语义拖住。
- **问：翻转增强会不会造成标签错误？**
  答：翻转在点云层做（x 取负），答案文本严格互换 left↔right，且已验证 50 类动作名互换后仍在类内；val/test 不翻转，无评估泄漏。
- **问：为什么不用点云编码器？**
  答：先验证视觉通路可行性与瓶颈所在，成本最低；当前瓶颈是数据表达（时序/镜像）而非编码能力，先修数据。若 E6 无效再换路线。
- **问：怎么保证没有数据泄漏？**
  答：按被试划分；图里不渲染任何标签；第 4 格只画轨迹不标位移数值；val/test 不做翻转增强。
- **问：E5 学新任务会不会忘旧任务？**
  答：同口径 test 对比 E4：top1 0.275→0.240、top5 0.690→0.665，属 200 题内约 7 题波动，判定未遗忘，且有 train 集遗忘监控双保险。

**口径警告（组会必讲）**：train 快评 0.40 vs 0.27/0.29 不可比——新 train 含一半镜像样本，天然更难。跨口径可比的是 test。

**解读**：
- 镜像增强在生成式口径生效：fine 0.233→0.300（历史最佳），coarse 0.867→0.900，json 0.804→0.829。
- 新任务均值 0.816 与旧 0.812 持平 → 数据翻倍+新题型没有稀释多任务能力。
- 似然口径 top5 0.690→0.600 下降 9pp → 轨迹图替换图例面板后，“类名似然排序”这一读出方式受干扰；同一新 E4 权重用线性探针读出 top5 即回 0.695（743 样本丐版），指向**读出头问题而非特征退化**。
- movement 档位 0.50→0.533、数值 0.80→0.83：轨迹图有正向作用但未达预期 0.7，档位判断仍是弱项（推测：still/slight/notable 边界本身模糊，需人审确认判分口径）。

**判别式探针**（读出头消融，支撑“瓶颈在生成式读出而非特征”的论点）：
- 动机：似然排序把 50 个类名当文本逐条打分，读出弱；冻结模型抽最后隐状态训线性头 = 特征本身的上限。
- 修过两个 bug：torch.argsort 需显式 descending=True（升序会精确得到 0%）；train 特征量 743（每对 1 帧）→ 加 --train_per_pair 8 提到约 5900。
- 丐版结果（743 训练样本）：**top1 0.255 / top5 0.695** —— top1 与似然持平、top5 +9.5pp；完整版（5900 样本）进行中。

## 10. A 方案（2026-10-22 待跑）：把读出做到特征上限

**为什么做**：E6 生成式 fine 已到 0.300，但似然 top5 反降到 0.600，而同一份权重换线性头读出 top5 就有 0.695。说明“50 个类名逐条算似然”这种读出方式本身是瓶颈，不是特征退化。A 方案就是把读出做到极致，回答“模型到底看懂了多少”。

**脚本**（`scripts/probe_aug.py` / `probe_ensemble.py` / `run_probe_aug.sh`）：

| 设计点 | 做法 | 理由 |
|---|---|---|
| 镜像监督 | 训练特征掺入 `*flip.png`，标签用 `swap_lr` 互换 | 镜像版外观对应镜像类，监督一致；直接压制 61% 的左右镜像错误 |
| 特征 | 中层末token + 中层图均值 + 末层末token + 末层图均值（4×1536=6144 维） | 中层特征更“通用”，末层更“任务化”，拼接互补 |
| 超参搜索 | 按**被试**分组 4 折 CV，搜 头（linear/cos/mlp）× lr × wd × epochs | 与 test 的跨被试口径一致，避免用被试指纹选出虚高配置 |
| 稳定化 | 特征标准化（均值方差只来自 train）+ 5 个随机种子概率平均 | 减少 ±1~2pp 抖动 |
| 集成 | E4/E5 概率平均 + 特征拼接后重训一个头 | 两个权重看到同一张图的不同抽象层，拼接保留互补性 |
| 口径 | 全量 test（6000 题，非 200 题）+ 同时报 50 类与 39 类镜像合并 | 200 题有 ±3pp 抖动；39 类去掉无关的左右歧义 |

**防呆**：`data/images/train` 无 `*flip.png` 会直接报错中止（静默丢掉镜像增强会让结论失真）；train 特征里镜像占比 <35% 同样中止；缓存键含 `train_per_pair`/`limit`，避免不同采样设置互相覆盖。

**跑法**（开机后一条命令，约 40~60 分钟）：

```bash
bash scripts/run_probe_aug.sh          # LIMIT=0 全量; 先验证流程可用 LIMIT=200
```

**预期（推测，未验证）**：50 类 top1 0.34~0.40、top5 0.75~0.80；39 类 0.45~0.52。**不会到 0.60** —— 0.60 需要换 7B 或改渲染（T=6 帧），A 方案只负责把现有权重的上限量出来。

**答辩说法**：分类指标用的是“冻结模型 + 判别式头”，这是标准线性探针协议（与 VLM 评测惯例一致），测的是表征质量；生成式 fine（0.300）是模型自己写答案的口径，两者同时报，不混用。


## 11. A 方案实测结果（2026-10-22，全量 test 6400）

**配置**：PER_PAIR=4（每被试每动作 4 原图 + 4 镜像），train 特征 5944，test 6400（8 个 `(被试,动作)` 组），SEEDS=5，LIMIT=0 全量。服务器 RTX 4090，从 `d181798` 起跑。

| 模型 | 50 类 top1 | 50 类 top5 | 39 类 top1 | 39 类 top5 | 分组 CV | 随机折 CV |
|---|---|---|---|---|---|---|
| E4 aug | 0.331 | 0.723 | 0.418 | 0.773 | 0.354 | 0.375 |
| E5 aug | 0.339 | 0.732 | 0.429 | 0.779 | 0.354 | 0.377 |
| 双模型集成（概率平均）| **0.342** | **0.732** | 0.428 | **0.781** | — | — |
| 双模型集成（特征拼接）| 0.341 | 0.731 | **0.429** | 0.780 | 0.354 | 0.377 |

**三个结论**：

1. **50 类天花板 ≈ 34%**。加了镜像监督、6144 维特征拼接、分组超参搜索、5 种子平均之后，比旧探针（0.34/0.755，200 题口径）几乎没变。读出端已经做到特征上限，0.34 不是"没调好"，是"特征里就这么些信息"。
2. **不是被试指纹虚高**。同被试随机折 0.377 vs 跨被试分组折 0.354，只差 **2.1~2.3pp**。说明探针没有靠记住被试身份取巧；50 类卡住的原因是"细粒度 + 4 帧输入"本身。
3. **双模型集成收益可忽略**（+0.3pp）。E4/E5 是同一训练轨迹上的两个点，特征高度相关，集成没有互补信息。后续提分只能动输入（帧数/时频图）或模型规模（7B），不能再在读出端做文章。

**答辩说法**：A 方案把"读出方式不好"这个假设证伪了 —— 换最强读出头，50 类也只到 0.342。这条负结果本身就是结论：跨被试 4 帧 50 类的信息瓶颈在输入，不在头。

## 12. E7 多轮追问理解模型（2026-10-22 完成）

**目标**：从"分类器"转成 RF-GPT 式"能理解、能追问、能解释"的模型；50 类分类降为探针附录。

**数据**（`scripts/synthesize_chat.py`）：每张图合成 2~4 轮对话，轮型为
`action`（做什么）→ `evidence`（你怎么看出来的）→ `quantity`（运动量/高度/位移数值）→ `counterfactual`（镜像反事实：左右互换后是什么动作）。
train 71,328 条（11,888 图 × 3 + 11,888 镜像 × 3）、val 1,500、test 6,000；与 instruct_train 合并后 **e7_train 共 190,208 条**。

**训练**：从 E5 续训，lr 2e-5，1600 步，4.8 s/step（约 2 小时 10 分），每 400 步存快照（step400/800/1200/1600）。

| action（39 类镜像合并）| 0.350 | |
| action（3 粗类）| **0.890** | |
| evidence（解释所用的证据）| **0.699** | 5 项证据（水平位置/深度/运动量/姿态/垂直尺寸）逐项对 |
| quantity（数值题）| **0.921** | 容差 max(0.15, 20%) |
| counterfactual（左右互换）| **0.851** | 必须给出 swap_lr 后的动作名 |

**答辩说法**：E7 证明"让模型理解雷达点云"这条路走通了 —— 它能说清"人在哪、站还是坐、动多少、多高、走了多远"，能解释判断依据，能在被追问镜像反事实时正确互换左右，且 300 条对话里没有一次左右自相矛盾。分类探针的 0.34 与生成式的 0.22 是两种口径，不混用；跨被试 4 帧 50 类的信息瓶颈在输入侧，不在模型或读出。

## 13. 架构重设计文献调研：信号原生 LLM（2026-10-25）

**路线变更（已定）**：不再以"点云渲染图 → 视觉编码器"为主路；主线改为 **原始雷达信号 → 自研转换模块 → LLM 嵌入空间**，2B 级模型（基座可换），视觉分支降级为备用；评测协议允许重设；远期目标是"一个能理解多种雷达信号的 LLM"。本节只做文献与空白梳理，尚未动代码。

### 13.3 三条技术路线归纳

1. **造图路线**（RF-GPT、PReD、MERLIN）：信号 → 可视化表示 → 现成视觉编码器 → adapter → LLM。
   优点：直接复用预训练 ViT，训练成本低。缺点：分辨率、色图映射、视图选择都变成人为瓶颈；RF-GPT 自己也承认这是"借用视觉编码器"。
2. **离散码本路线**（RadarLLM）：点云 → VQ-VAE → 离散 radar token → 扩词表 → 联合预训练 + 指令微调。
   优点：**每帧只 1 token**，序列极短，可做 T→R 生成。缺点：早期量化形成信息瓶颈，重建目标未必保留任务相关结构（mmMind 明确以此立论）。
3. **连续 token 路线**（mmMind、PointLLM 谱系）：点云 → 时空编码器 → 连续 token → projector → LLM；用 pose/几何做仅训练期监督。
   优点：保留运动学细节，无量化损失。缺点：依赖强监督与两阶段对齐。

### 13.4 关键数字对照（用于判断"该不该换大模型"）

- **模型规模不是主因**：RadarLLM 消融里 T5-small（60M）ROUGE-L **36.0**，GPT2-M（355M）**35.4**，DeepSeek-R1（1.8B）**37.4**。60M → 1.8B 只涨 1.4，说明收益在 tokenizer 与数据，不在参数量。→ 我们留在 2B 是合理的。
- **真实域仍是硬骨头**：RadarLLM 虚拟 BERTScore **83.3**，真实只有 **81.4**（与 AvatarGPT 基线持平），真实 BLEU-4 仅 **5.0**；真实数据只有 375 条序列。
- **结构先验值钱**：去掉模板锚点 ROUGE-1 −27.3%；去掉掩码训练 BLEU-4 −23.7%；去掉嵌入损失 CIDEr −54.2%。
- **监督密度**：mmMind 用 17.9 h 真实数据 + pose 监督拿到 BERTScore 86.8；RadarLLM 用 13,308 条合成序列 + 375 条真实只到 81.4。→ 真实数据 + 强监督 > 纯合成堆量。

### 13.5 空白与创新候选

**A. RT-native：首个"原始雷达张量 → LLM"的人体行为模型（最强）**
现有工作全部停在点云（RadarLLM / mmMind / mmWave-QA）或频谱图（RF-GPT / PReD / MERLIN）。M4Human 同时给了 RT 与 RPC，可做**同数据、同划分、同 LLM 的表示粒度受控对比**：
`RT` vs `RPC` vs `现渲染图`，三档只改输入，量化"点云化损失了多少"。
- 卖点：不是"又一个 radar LLM"，而是**第一次把雷达信息损失算清楚**。
- 前置：RT 可得（见 13.6）。

**B. 配置条件化 tokenizer：一个模型吃多种雷达**
把带宽、帧率、阵列几何、距离分辨率作为条件向量注入编码器，做跨 60/77 GHz、跨数据集的迁移评测。
- RadarLLM 只针对 AWR1843；mmMind-Bench 有多频段但没做跨配置迁移；WiFo-MiSAC 统一了异构信号但不是 LLM、不做人体。→ 这个交叉点是空的。

**C. 统一 radar token 空间（多表示共享码本）**
共享 codebook + 表示特化 adapter，RT / RPC / 微多普勒共用一套"雷达词"。
- 对标 mmWave-QA 的"全局动作体系对齐"，但把文本对齐升级为**可训练的共享 token 空间**；这也是"理解各种雷达信号"最直接的技术形态。

**D. 更密的仅训练期监督**
M4Human 有 MoCap mesh（比 mmMind 的 3D pose 更密），可做 mesh/pose 双监督 + 物理一致的反事实（镜像、左右互换）。
- 直接把 mmMind 的"pose-guided"推到"mesh-guided"，且数据量更大（661,132 帧）。

**E. 评测创新：信号理解探针**
现有工作只报 caption 指标与 QA 准确率；我们已有 9 题型、quantity、反事实、evidence 的评测资产，可扩成：
SNR 退化、遮挡/多径、跨配置、跨被试、镜像反事实。
- 能回答"模型是在看图/看先验，还是真的在看信号"。

**推荐叙事**：以 A 为主贡献（RT-native + 粒度受控对比），B 为通用性贡献，E 为评测贡献；C/D 作为后续扩展。

### 13.6 风险与待确认（按优先级）

1. **RT 是否公开可下载、张量维度、单帧体积、总容量**——未核实。粗估（**推测，勿引用**）：若 range-Doppler-angle 为 256×64×8、float16，则 ≈262 KB/帧，661K 帧 ≈ **173 GB**；若 complex64 则翻倍。必须先拿到一帧真实规格再定存储与采样方案。
2. **RT 的坐标/阵列约定**：距离-多普勒-角度顺序、虚拟阵列排布、是否已做静态杂波抑制，决定前端是 3D 卷积还是可学习 FFT。
3. **许可与对齐**：MoCap mesh 与 RT/RPC 的时间戳对齐格式；数据能否二次发布派生标注。
4. **旧缺陷不能继承**：`Z_SIT=0.85` 阈值误判、9 题型答案与 caption 同源模板——新管线必须重做标注，不要复用旧模板。
5. **算力**：2B + 每 clip 8~16 token 可行；若按 mmMind 的 75 token/clip（5 s@15 Hz），序列仍可控，但 RT 前端显存需实测。

## 14. I/Q 数据管线与编码器（2026-10-29）

**决策**：主线只做 **I/Q**。RT 暂不做——本地没有处理包，且 M4Human 的 RT 是 x-y-z 功率体素，**没有 Doppler、没有相位**；以后最多做对照。

### 14.1 数据转换

- `.mat` → int16 I/Q LMDB：key `[subject, action, frame]`；header `<IIIIf`；int16 `(2, 320, 151)` = I plane + Q plane；每帧一个 float32 scale。
- 已完成：p1 **28,573** 帧；p2 **19,072** 帧（1 帧损坏）；p17 **33,987** 帧（0 损坏）；量化 RRMSE **5.5e-5**。
- 体积：p1 5.2 G / p2 3.5 G / p17 6.2 G；全量 20 人约 **119 G**。
- p19 仍在下载。

### 14.2 轴校验（关键结论）

- 直接对 151 点做 IFFT：峰在 **0 m**，被近距直达波/静态杂波压住。
- 帧间背景相减 + Hann + IFFT：峰 **2.17–2.21 m**，与同帧 RPC 中位数 **2.61 m**（p10 2.31 / p90 4.82）一致。
- 轴顺序：**16 天线对 = `pairs` 第 0 列，20 chirp = 第 1 列**；反向后 Doppler 谱变成平顶，确认选对。
- **前端必须包含帧间杂波抑制**，否则 range 峰落在 0 m。

| 文件 | 作用 |
